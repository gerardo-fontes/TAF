# TAF Web Frontend — Phased Implementation Plan

Agent-executable plan for building a web frontend for the
[Test Automation Framework (TAF)](https://github.com/MariaDB/TAF), the MariaDB
Foundation's Perl test-automation framework for database benchmarking.

This directory is a **plan**, not code. Each `PHASE-*.md` file is a
self-contained brief that a coding agent can execute top to bottom. Work the
files **in numeric order**. Each phase ends with an explicit gate — do not start
the next phase until the current gate is satisfied.

---

## The three features to build

Requested by the TAF maintainer (Jonathan "jeb" Miller), MariaDB Foundation:

1. **Results listing** — browse automated benchmark runs, tick two or more, hit
   *Compare*.
2. **Compare page** — baseline vs candidate, per-thread deltas, regression
   status.
3. **Dashboard** — automated results feed; click a run to open baseline vs
   incoming, ATR-dashboard style.

Explicit constraint from the maintainer: *"Does not have to be super fancy."*
Fidelity to TAF's comparison semantics beats visual ambition throughout this
plan.

## Global conventions — apply in every phase

### Repository conventions

- **License header is mandatory on every new file.** Every `.pm`, `.sql`, `.java`,
  and `.properties` file in TAF opens with the GPLv2+ block, including `Created:`
  and `Last Modified:` lines and the copyright line
  `Copyright (c) <year> MariaDB Foundation and Jonathan "jeb" Miller`. Every new
  `.ts`, `.tsx`, `.sql`, `.json`, `.yml`, `.css` file you add must carry the same
  header, adapted to the file's purpose. The maintainer's stated standard is
  *"contributor-proof"* code with explicit, inspectable behaviour.
- **Never modify a Perl file.** No edits to `taf.pl`, `libs/**`, `scripts/**`,
  `test_suites/**`, or `properties/**`. The frontend is additive and reads the
  database; it must not require a single change to the Perl framework. If you
  believe a Perl change is required, **stop and report** — do not make it.
- **All new code lives under `web/`.** Top-level `web/` directory, nothing
  scattered. Rationale: TAF's README states the framework requires *"No runtime
  to install, no virtual environment to manage, and no dependency chain to
  maintain."* Isolating Node under `web/` keeps that guarantee true for the
  Perl harness itself. If the maintainer prefers a different path, that is a
  Phase 0 decision.
- **Do not add `.github/workflows/` without explicit maintainer sign-off** in
  the Phase 0 issue. The repository currently has no `.github` directory at all.
- **The database is read-only to the frontend.** Phase 1–6 never `INSERT`,
  `UPDATE`, or `DELETE`. The one exception is a Phase 0 proposal for baseline
  management (`set_baseline`), which is a separate, opt-in feature — do not build
  it unless the maintainer asks.
- **No fabricated data in committed fixtures.** Seed data is either generated by
  a documented script against a real schema, or committed as clearly-labelled
  test fixtures under `web/test/fixtures/` with a header stating it is synthetic.

### Agent behaviour

- **Read `CONTEXT.md` first** in every session. It carries the verified schema,
  file paths, and config keys so you never guess a column name.
- **Stop-and-ask gates are real gates.** Phases 0, 2, and 3 contain a gate that
  requires a human decision. Report and wait. Do not guess a maintainer's
  preference.
- **Never fabricate a metric.** Every number rendered comes from
  `results.metric_value` or from a computation over it. No interpolation, no
  smoothing, no demo numbers in production code paths.
- **Verify, then claim.** Each phase's Definition of Done lists commands to run.
  Run them. Paste real output into the PR description. Do not write "tests pass"
  without having run them.
- **Small PRs.** One phase ≈ one PR. A reviewable diff beats a large one — the
  maintainer is one person and a Perl specialist, so every PR must be easy to
  audit without deep frontend knowledge.

### Definition of Done (global)

Every phase is done when **all** hold:

- [ ] `npm run lint` — clean, no `--max-warnings` overrides
- [ ] `npm run typecheck` — clean under `strict: true`
- [ ] `npm run build` — succeeds
- [ ] `npm test` — passes
- [ ] Every new file carries the GPLv2+ header
- [ ] `README` section in `web/README.md` updated with what changed and how to run
- [ ] PR description quotes the real command output, states which Phase-0
      decisions this PR depends on, and lists the open questions for the maintainer

## Working directory

The agent works in a **fork**, never in `MariaDB/TAF` directly:

```
https://github.com/<your-handle>/TAF.git
```

Clone with the TAF Perl tree intact:

```bash
git clone https://github.com/<your-handle>/TAF.git
cd TAF
git remote add upstream https://github.com/MariaDB/TAF.git
```

A disposable database for local work (see Phase 1):

```bash
docker run -d --name taf-db \
  -e MARIADB_ROOT_PASSWORD=taf \
  -e MARIADB_DATABASE=taf_backend \
  -p 3306:3306 mariadb:11
```

Apply the schema:

```bash
docker exec -i taf-db mariadb -uroot -ptaf < \
  libs/reporter_libs/backend/backend_sql/create_backend.sql
```
